# Запуск: статический сайт на текущем хостинге

Архитектура: на проде только файлы (HTML, JS, CSS) плюс один PHP-скрипт для формы. Node, Postgres и Docker нужны только на машине владельца: там агент правит базу и собирается сайт. Старые фото остаются в `wp-content/uploads/` на хостинге по тем же URL.

## Требования к хостингу (проверить заранее)
- Apache с `mod_rewrite`, `mod_headers`, `mod_expires` и разрешённым `.htaccess` (`AllowOverride All`).
- PHP 8.1+ с работающей `mail()` (для `send.php`). Если письма не уходят, заменить `mail()` на SMTP (PHPMailer) в `deploy/send.php`.
- Способ заливки: SFTP/FTP-клиент или SSH (rsync). Для 40 МБ сайта хватает любого.
- Место: сайт ~45 МБ плюс текущие uploads (~5,5 ГБ).

## Что собирается
`npm run build:static` (в `apps/web`): `next build` с экспортом в `apps/web/out`, затем `.htaccess` (HTTPS, заголовки безопасности, 301 для старых WP-адресов и `/?p=ID`, запрет всего PHP кроме `send.php`), `send.php`, проверки (нет лишнего PHP, нет `localhost`/`orientir.local` в HTML). Адрес сайта в canonical/sitemap/RSS фиксирован `https://orientir.by` (переопределяется `PUBLIC_SITE_URL`).
Перед сборкой один раз: `copy deploy\send-config.example.php deploy\send-config.php`, вписать адрес получателя и домен отправителя.

## Порядок запуска
1. **Подготовка (за несколько дней).** Проверить хостинг по списку выше. Сделать полную резервную копию текущего WordPress (файлы и БД) вне хостинга.
2. **Чистка uploads.** Старый WP был заражён (инъекция скрипта в БД), и сам он будет удалён, но папку uploads мы оставляем, а в ней могут лежать подложенные скрипты. Перед использованием папки `wp-content/uploads/` на проде: удалить из неё все `.php`, `.phtml`, `.phar`, `.js` и подозрительные файлы (поиск: `find uploads -type f \( -name '*.php*' -o -name '*.phtml' -o -name '*.phar' \)`), затем положить туда `deploy/uploads.htaccess` как `.htaccess`. Сменить пароли хостинга, FTP и БД.
3. **Заморозка контента.** Объявить, что в WP больше ничего не публикуется. Сделать свежий дамп и локально прогнать `npm run etl` (идемпотентный: обновляет изменённое, удаляет пропавшее из WP, но откажется удалять больше 20% записей разом) и `npm run etl:verify`.
4. **Сборка и проверка локально.** `npm run build:static`, затем отдать `out/` любым статическим сервером и прогнать `npm run golden -- --next=http://localhost:PORT` (должно быть 0 расхождений). Просмотреть главную, запись, рубрику, поиск, форму.
5. **Заливка на staging-поддомен** (например `new.orientir.by`, указать его же в `deploy/send-config.php` как origin), проверить письмо из формы, заголовки (`curl -I`), редиректы (`/feed/`, `/?p=ID`, `/home/`, `/blog/`).
6. **Переключение.** Боевой WordPress выводим из эксплуатации, чистить его от заражения не нужно. Сначала проверить, что резервная копия (файлы и БД) лежит вне хостинга и восстанавливается. Затем перенести старый WP из корня в закрытую папку `old-wp` (`Require all denied`), оставив в корне только `wp-content/uploads/`. Залить содержимое `out/` (включая `.htaccess`, `send.php`, `send-config.php`) в корень. Сразу проверить главную, запись, картинку из uploads, форму.
7. **После.** Отправить sitemap в Яндекс.Вебмастер и Google Search Console (`https://orientir.by/sitemap.xml`), следить 404 в логах хостинга неделю. Если откат не понадобился (рекомендую подождать месяц), удалить `old-wp` с хостинга окончательно, оставив резервную копию вне хостинга.

## Откат
Вернуть имя папки старого WP и убрать новый `.htaccess`. Новый сайт при этом не затрагивается.

## Обновление сайта после запуска
Агент правит базу через CLI (`AGENT_CLI.md`), затем `npm run build:static` и заливка `out/` поверх (или только изменившихся файлов, если заливка через rsync). Для автоматизации заливки нужны доступ по SSH или FTP и решение, где хранить ключ.

## Известные ограничения статического варианта
- Правки видны на сайте только после пересборки и заливки.
- Время публикации и срок жизни (`publishedAt`, `expiresAt`) применяются при сборке: запись с будущей датой появится после первой сборки после этой даты.
- Поиск клиентский: индекс `search-index.json` (~0,6 МБ) содержит заголовки и первые 2000 символов текста.
- Форма отправляет письмо, заявки в базе не сохраняются.
- Картинки отдаются как есть (оптимизатор Next недоступен); для скорости позже можно подставлять готовые миниатюры WP.
